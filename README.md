# VK AI Bot

AI-бот для сообщества ВКонтакте. Отвечает на личные сообщения с помощью OpenAI,
помнит контекст, ведёт несколько диалогов на пользователя и умеет общаться в шести режимах.
Управление — кнопками в чате или текстовыми командами.

- Получает сообщения через **Bots Long Poll API** (библиотека [VKBottle](https://github.com/vkbottle/vkbottle)), публичный сервер не нужен.
- Отвечает через **OpenAI Chat Completions API**.
- Хранит диалоги пользователя (у каждого — последние 20 сообщений) в `users/{user_id}.json`.

## Установка

Нужен Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate  # macOS/Linux
# .venv\Scripts\activate   # Windows PowerShell
pip install -r requirements.txt
cp .env.example .env
python main.py
```

## Настройка `.env`

| Переменная | Обязательна | Что это |
|---|---|---|
| `VK_TOKEN` | да | Ключ доступа сообщества |
| `VK_GROUP_ID` | да | Числовой ID сообщества |
| `OPENAI_API_KEY` | да | Ключ OpenAI API (`sk-...`) |
| `OPENAI_MODEL` | нет | Модель OpenAI, по умолчанию `gpt-5.4-mini` |

Если обязательной переменной нет, бот не стартует и пишет, какой именно.

### Как получить ключи ВКонтакте

1. **Ключ сообщества:** Управление сообществом → Дополнительно → Работа с API → Ключи доступа →
   **Создать ключ**. Отметьте права **«Сообщения сообщества»** и **«Управление сообществом»**.
2. **Long Poll:** там же, вкладка **Long Poll API** → включить, версия API — последняя.
   На вкладке **Типы событий** включите **«Входящее сообщение»** (`message_new`).
3. **Сообщения:** Управление → Сообщения → включить **«Сообщения сообщества»**;
   там же в **Настройках для бота** включите **«Возможности ботов»**.
4. **ID сообщества:** число из адреса `vk.ru/club123456789` или в разделе «Работа с API».

### Ключ OpenAI

[platform.openai.com/api-keys](https://platform.openai.com/api-keys) → **Create new secret key**.
На аккаунте должен быть положительный баланс.

### Антивирус и ошибка `CERTIFICATE_VERIFY_FAILED`

Некоторые антивирусы (например, Касперский) проверяют HTTPS и подменяют сертификат сайта своим.
Python по умолчанию доверяет только своему встроенному списку сертификатов и такое соединение
отвергает. Поэтому бот при старте подключает [truststore](https://github.com/sethmlarson/truststore)
и проверяет сертификаты по системному хранилищу ОС — так же, как браузер. Проверка сертификатов
при этом не отключается.

## Кнопки

Главное меню — постоянная клавиатура внизу чата (появляется после `/start` или первого сообщения):

| Кнопка | Что делает |
|---|---|
| ➕ Новый диалог | Начать новый разговор с чистой памятью; старые диалоги сохраняются |
| 📋 Список диалогов | Активный диалог и его режим; переключение, ✏️ переименование, 🗑 удаление |
| ⚙️ Настройки | Сводка (диалог, режим, сообщений в памяти, модель) и 🧹 очистка истории |
| 🎭 Сменить режим | Выбор режима для активного диалога |
| ❓ Помощь | Подсказка по кнопкам и командам |

- У каждого диалога своё название, режим и память. Диалогов — до 6
  (лимит VK: не больше 10 кнопок в клавиатуре под сообщением).
- Переименование: выберите диалог, затем отправьте новое название (до 30 символов).
- Удаление и очистка истории спрашивают подтверждение. Если удалить последний диалог,
  создаётся пустой «Основной диалог».
- Нажатия кнопок обрабатываются локально и в LLM не отправляются.

## Режимы

| Режим | Команда | Стиль |
|---|---|---|
| Обычный помощник | `/mode assistant` | Понятно и по делу |
| Программист | `/mode programmer` | Код, ошибки, архитектура |
| Преподаватель | `/mode teacher` | Просто, с примерами и проверкой понимания |
| Бизнес-консультант | `/mode business` | Бизнес-задачи: цифры, риски, план действий |
| Дружелюбный собеседник | `/mode friend` | Неформально, коротко, с эмодзи |
| Эксперт | `/mode expert` | Структурированно, со списками и уточнениями |

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие, список режимов и главное меню |
| `/mode` | Показать режим активного диалога |
| `/mode <режим>` | Сменить режим активного диалога |
| `/reset` | Очистить историю активного диалога (режим сохраняется) |

Команды обрабатываются локально и не отправляются в LLM. Любой другой текст уходит в модель
вместе с историей активного диалога.

## Структура

```
main.py              — точка входа: логирование, конфиг, запуск бота
bot/config.py        — чтение и проверка .env
bot/vk_client.py     — VKBottle, Long Poll, обработка кнопок, команд и сообщений
bot/keyboards.py     — клавиатуры: главное меню и кнопки под сообщениями
bot/llm_client.py    — запросы к OpenAI Chat Completions
bot/memory.py        — диалоги пользователей в users/{user_id}.json
bot/modes.py         — режимы общения и system-промпты
users/               — данные пользователей (в git не попадают)
```

## Как это работает

1. Пользователь пишет сообществу в личные сообщения (сообщения из бесед бот игнорирует).
2. Если это кнопка или команда — бот отвечает сам, без LLM.
3. Иначе бот берёт активный диалог, отправляет в OpenAI system-промпт его режима,
   историю и новое сообщение, сохраняет пару «вопрос — ответ» и отвечает.
4. Если OpenAI недоступен, пользователь получает вежливое сообщение о временной проблеме,
   ошибка пишется в лог, а история не меняется.

Формат `users/{user_id}.json` (файлы старого формата с одним диалогом переводятся автоматически):

```json
{
  "dialogs": [
    {
      "id": 1,
      "title": "Основной диалог",
      "mode": "assistant",
      "history": [
        {"role": "user", "content": "Меня зовут Vik"},
        {"role": "assistant", "content": "Приятно познакомиться, Vik!"}
      ],
      "created_at": "2026-10-15T18:00:00+00:00"
    }
  ],
  "active_id": 1,
  "next_id": 2,
  "pending": null,
  "updated_at": "2026-10-15T18:00:00+00:00"
}
```

`pending` — незавершённое действие (например, бот ждёт новое название диалога).
